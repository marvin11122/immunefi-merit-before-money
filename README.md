# Merit Before Money

## A note to Immunefi and the security community

A private evidence package concerning Ethena exists. It includes a machine-checked
mathematical proof and local fork tests. This repository deliberately publishes
none of the finding, affected code paths, addresses, parameters, exploit steps,
or proof files. It is a notice that evidence exists—not a vulnerability report
or a public disclosure of technical details.

## The process problem

On 24 November 2026, the authenticated Immunefi Studio landing page displayed
“invite-only.” Its invite-request flow said that, after receiving an invite, a
researcher must be ready to buy 300 credits (300 USDC) within 24 hours. No invite
was requested and no credits were purchased.

That may be a business decision. It is also a peculiar design for a service
whose stated purpose is to help evaluate security evidence: the researcher is
asked to demonstrate willingness to pay before being allowed to learn whether
the evidence can even be reviewed. A paywall is not a severity rubric. An invite
gate is not a technical rebuttal. A purchase commitment is not a proof check.

The author’s self-assessment is deliberately uncredentialed: I am dumb, I use
drugs, and I spent four years learning mathematics. I did so, among other
reasons, to make a narrow claim machine-checkable. This is not offered as proof
that every reviewer lacks competence. The joke is more institutional than
personal: if a self-described idiot can spend years formalizing a result, while
the evidence cannot reach review without first passing a commercial gate, the
obvious bottleneck may not be the researcher’s IQ.

## What this page does—and does not—claim

- It claims that a private evidence package exists.
- It does not claim that a bounty has been accepted, that a reward is owed, or
  that a production exploit has been established.
- It does not publish technical details or invite anyone to test a live system.
- The material remains withheld pending a suitable responsible-review channel.

If Immunefi wants to rebut the evidence, the efficient way is to provide a
review path that evaluates the evidence. The purchase flow cannot establish
whether a mathematical statement is true.
